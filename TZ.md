# Техническое задание: GreenFit

## 1. Название и концепция

**GreenFit** — веб-сервис для подбора комнатных растений по параметрам микроклимата
квартиры.

**Проблема.** Начинающие цветоводы часто покупают растения, которые не подходят их
условиям (мало света, сухой воздух, неподходящая температура, есть домашние животные),
и растения гибнут. Обычные каталоги лишь показывают карточки и в лучшем случае
фильтруют их.

**Решение.** GreenFit не просто фильтрует каталог, а рассчитывает **процент
совместимости** каждого растения с конкретным помещением по шести взвешенным критериям
и объясняет оценку по каждому пункту. Температуру и влажность можно автоматически
подставить из данных о погоде (Open-Meteo). По накопленным подборам строится
статистика (Pandas + Chart.js).

## 2. Целевая аудитория и роли

Сервис рассчитан на владельцев квартир и начинающих цветоводов.

| Роль | Возможности |
|------|-------------|
| **Гость** | Ввод параметров помещения, получение ранжированного списка с пояснениями, просмотр статистики |
| **Зарегистрированный пользователь** | Всё вышеперечисленное + сохранение и просмотр истории своих подборов |
| **Администратор** | Управление каталогом растений и категорий через админ-панель Django |

## 3. Схема данных (сущности)

Реализовано **4 связанные пользовательские модели**.

### PlantCategory — категория растений
- `name` — CharField, название категории
- `slug` — SlugField, идентификатор для URL
- `description` — TextField, описание

### Plant — растение
- `name` — CharField, название
- `scientific_name` — CharField, научное название
- `category` — ForeignKey → PlantCategory
- `light_needs` — choices: low / medium / bright
- `humidity_needs` — choices: low / medium / high
- `temp_min`, `temp_max` — IntegerField, диапазон температур
- `toxicity` — BooleanField, токсичность для животных
- `care_difficulty` — choices: easy / medium / hard
- `water_frequency` — choices: rare / regular / frequent
- `max_height` — IntegerField, максимальная высота, см
- `image` — ImageField, фото (необязательно)
- `description` — TextField, описание

### RoomCondition — условия помещения
- `user` — ForeignKey → User (необязательно, для гостя пусто)
- `light_level` — choices: low / medium / bright
- `humidity` — choices: low / medium / high
- `temperature` — IntegerField
- `room_size` — choices: small / medium / large
- `has_pets` — BooleanField
- `care_time` — choices: minimal / average / much
- `created_at` — DateTimeField, дата подбора

### MatchResult — результат подбора
- `room` — ForeignKey → RoomCondition
- `plant` — ForeignKey → Plant
- `match_score` — FloatField, процент совместимости
- `reasons` — TextField, пояснения по критериям

## 4. Пользовательские сценарии (User Stories)

1. **Подбор растений.** Гость заполняет форму из шести параметров помещения и получает
   ранжированный список растений с процентом совместимости и пояснением по каждому из
   шести критериев.
2. **Автозаполнение погоды.** Пользователь вводит город и нажимает «Узнать погоду» —
   через AJAX система запрашивает Open-Meteo и подставляет текущие температуру и
   влажность в форму.
3. **История подборов.** Зарегистрированный пользователь открывает раздел «История» и
   видит список своих прошлых подборов с лучшим вариантом и датой; по клику открывается
   полный результат.
4. **Статистика.** Любой пользователь открывает страницу статистики: средний процент
   совместимости, топ-5 растений и распределение результатов по сложности ухода
   (интерактивные графики Chart.js на данных, посчитанных Pandas).
5. **Администрирование.** Администратор добавляет, редактирует и удаляет растения и
   категории через админ-панель с поиском и фильтрами.

## 5. Алгоритм подбора

Для каждого растения рассчитывается оценка от 0 до 100 % как сумма баллов по шести
взвешенным критериям (веса в сумме дают 100):

| Критерий | Вес | Как считается |
|----------|----:|---------------|
| Освещение | 25 | Порядковая близость уровней (low/medium/bright): совпадение — 100 % веса, разница на 1 уровень — 50 %, на 2 — 0 % |
| Температура | 20 | 100 % веса, если температура в диапазоне `temp_min…temp_max`; за каждый градус за пределами оценка линейно снижается (−10 % за °C) |
| Уход | 20 | Сравнение свободного времени пользователя со «спросом» растения (среднее от сложности ухода и частоты полива) |
| Безопасность | 15 | Если есть питомцы и растение токсично — 0 %, иначе 100 % |
| Влажность | 10 | Порядковая близость уровней low/medium/high (аналогично освещению) |
| Размер | 10 | Сравнение максимальной высоты растения с размером помещения |

Итоговый балл = Σ(доля × вес). Растения сортируются по убыванию балла. По каждому
критерию формируется текстовое пояснение, которое показывается на странице результата
и сохраняется в `MatchResult.reasons`.

Логика вынесена в отдельный сервисный модуль `selector/matching.py` и не зависит от
базы данных, что упрощает её тестирование.

## 6. Технологический стек и интеграции

- **Backend:** Python 3, Django 5.2 (LTS)
- **Внешний API:** Open-Meteo (геокодинг + текущая погода) через библиотеку `requests`
- **Аналитика:** Pandas — расчёт среднего балла, топ-5 и распределения по сложности
- **Frontend:** Bootstrap 5, Chart.js (интерактивные графики), Fetch API (AJAX)
- **База данных:** SQLite (разработка), PostgreSQL/MySQL (продакшен) через `dj-database-url`
- **Развёртывание:** WhiteNoise для статики, конфигурация через переменные окружения

## 7. Изменения в процессе реализации

В ходе разработки в исходное ТЗ внесены следующие непринципиальные уточнения:

- В модель `RoomCondition` добавлено поле `created_at` — нужно для сортировки и
  отображения истории подборов.
- Поле `Plant.image` сделано необязательным (`blank=True`); при отсутствии фото
  показывается изображение-заглушка.
- Категориям заданы латинские `slug` для аккуратных URL.
- Шкалы освещения и влажности у `RoomCondition` приведены к тем же значениям, что и у
  `Plant`, чтобы их можно было напрямую сравнивать в алгоритме.
- Добавлены сверх базового ТЗ (бонус): регистрация и личная история, AJAX-подстановка
  погоды, страница статистики с графиками Chart.js, набор модульных тестов.
